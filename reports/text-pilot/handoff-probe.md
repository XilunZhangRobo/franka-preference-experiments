# Handoff probe

This was one text-only cold choice and a follow-up with the same robot-side Astra agent. Case H was a new simulated user. The robot received no evidence about H's receiving hand before the first choice.

| Condition | Astra’s choice | Astra’s reason |
|---|---|---|
| Capped marker, both hands equally reachable, a side required, no memory about H | Recipient’s right | It called the choice an arbitrary tie-break and said it had no preference evidence. |
| Same scene, centered offer allowed | Midline, wait for reach | Let the person choose a hand through their action. |
| Same forced marker handoff after two behavior-only observations | Left | The person transferred a previous marker to the left to write. |
| Unseen screwdriver, both hands free | Left | The person used two other small tools with the left. |
| Screwdriver, left hand holding an assembly, right hand extended | Right | The current reach and occupied hand directly indicated the receiving hand. |

The simulated person described accepting a right-side offer, transferring the marker to the left, and writing. Later they reached for a brush with their left and used it. Neither description named a preference. The [authored note](notes/h-left-hand.md) made left-side placement tentative and recognized that the preferred receiving hand remained uncertain.

This one forced choice shows that Astra can select the right hand even when the scene gives it no reason to prefer either hand. Its explanation does not establish that it assumed right-handedness. To estimate a bias, repeat with fresh contexts, mirrored scenes, varied objects, and counterbalanced wording. The after-audit test was in the same agent context, so it does not isolate the written note from the prior interaction.
